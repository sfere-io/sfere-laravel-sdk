# Build Instructions: `sfere-sdk` — A Laravel SDK for Jitsu

You are a coding agent. Your task is to build a production-quality, open-source Laravel package called **sfere-sdk** that sends analytics events from a Laravel backend to **Jitsu** (jitsu.com), the open-source Segment alternative.

Read this entire file before writing code. Work through the phases in order, and do not move to the next phase until the current phase's acceptance criteria pass.

---

## 0. Ground rules for the agent

1. **Verify the API before coding against it.** Read Jitsu's official docs at `https://jitsu.com/docs/sending-data/http` (and the related "Server to Server" and "Segment Proxy" pages). If anything in this spec conflicts with the official docs, the docs win: follow them and note the difference in `NOTES.md`.
2. **Do not invent endpoints, fields or headers.** If something is unclear, implement the minimal documented behavior and leave a `// TODO(verify):` comment.
3. **Never break the host application.** Analytics failures must never throw into a user's request by default. Log them instead.
4. **Check current Laravel/PHP versions** before setting constraints in `composer.json`. Support every Laravel major that is still receiving security fixes at the time you build this.
5. Keep the public API small, typed and documented. Prefer clarity over cleverness.
6. Commit after each phase with a clear message.

## 2. Jitsu API facts to build against

Confirm each of these against the official docs first (rule 1).

**Base URL:** the user's Jitsu domain, e.g. `https://your-jitsu-domain.com`, or the Jitsu Cloud host. Self-hosted installs expose the same paths on their own domain.

**Endpoints:**

- `POST /api/s/s2s/{type}` — single server-to-server event. **This is the default endpoint for this SDK.**
- `POST /api/s/{type}` — single event (browser or s2s depending on key type).
- `POST /v1/batch` — Segment-compatible batch. Body: `{ "batch": [ ...events ], "context": { ...optional shared context } }`.
- `{type}` is one of `identify`, `track`, `page`, `group`, or `event` (generic: server reads the `type` field from the payload). Check the docs for whether `screen` and `alias` are accepted; support them only if documented.

**Authentication** (support all three, default to the header):

- Header `X-Write-Key: <write key>`
- HTTP Basic auth with the write key (follow the docs for exact username/password format)
- Query parameter `?writekey=keyId:keySecret`

**Event shape** (Segment-style). Every event the SDK sends must include:

- `type` — event type
- `messageId` — a UUID generated by the SDK (used for deduplication)
- `timestamp` — ISO-8601 time the event happened
- `sentAt` — ISO-8601 time the request was sent
- `userId` and/or `anonymousId` — at least one is required
- `context.library` — `{ "name": "sfere-sdk", "version": "<package version>" }`

Type-specific fields:

- `identify`: `traits` (object)
- `track`: `event` (string name, required), `properties` (object)
- `page`: `name` (optional), `properties` (object; may include `url`, `path`, `title`, `referrer`)
- `group`: `groupId` (required), `traits` (object)

## 3. Public API (what users will write)

```php
use Sfere\Facades\Sfere;

// Identify
Sfere::identify('user_123', ['email' => 'a@b.com', 'plan' => 'pro']);

// Track
Sfere::track('Order Completed', ['total' => 49.99], userId: 'user_123');

// Page (server-side page view)
Sfere::page('Pricing', ['url' => 'https://example.com/pricing'], userId: 'user_123');

// Group
Sfere::group('company_42', ['name' => 'Acme'], userId: 'user_123');

// Use the currently authenticated Laravel user automatically
Sfere::forUser(auth()->user())->track('Report Exported', ['format' => 'csv']);

// Anonymous visitor
Sfere::anonymous($anonymousId)->track('Signup Started');

// Override timestamp / context / integrations
Sfere::track('Imported', [], userId: 'u1', timestamp: now()->subDay(), context: ['source' => 'csv']);

// Force-send everything buffered now
Sfere::flush();
```

Also support a fluent builder for advanced cases:

```php
Sfere::event('track')
    ->name('Order Completed')
    ->userId('user_123')
    ->properties(['total' => 49.99])
    ->context(['campaign' => ['source' => 'newsletter']])
    ->send();
```

Requirements:

- `forUser()` accepts any `Authenticatable` (or `null`). It resolves the ID via `getAuthIdentifier()`. Allow a configurable resolver callback for custom IDs: `Sfere::resolveUserIdUsing(fn ($user) => $user->uuid)`.
- Calls must return quickly. Delivery mode (section 4) decides when the HTTP request actually happens.
- Validate input before sending (e.g. `track` without an event name, or missing both `userId` and `anonymousId`). On invalid input, throw `Sfere\Exceptions\InvalidEventException` **only** if `throw_exceptions` is true; otherwise log and drop.

## 4. Delivery modes

Configurable via `SFERE_DELIVERY`:

1. **`sync`** — send immediately with one HTTP request per event. Simplest; good for CLI and debugging.
2. **`batch`** (default) — buffer events in memory and send them to `/v1/batch`:
   - when the buffer reaches `batch.max_size` (default 100), and
   - automatically at the end of the request/command/job lifecycle (register flush via `app()->terminating(...)`, and listen for `JobProcessed`, `JobFailed` and console `CommandFinished`).
   - Enforce a maximum payload size (check the docs; default to 500 KB if undocumented) by splitting batches.
3. **`queue`** — dispatch a `Sfere\Jobs\SendEvents` job carrying the batch, on a configurable connection and queue name. The job uses the same transport and retry rules.

**Octane / long-running safety:** the buffer must not leak between requests. Flush and reset it on Octane's `RequestTerminated` event if Octane is installed. Do not store per-request state in static properties.

---

## 5. Transport and reliability

- Build the transport on Laravel's `Http` client (`Illuminate\Support\Facades\Http`) so users can test with `Http::fake()`.
- Configurable timeout (default 3 s) and connect timeout (default 2 s).
- Retries: retry on connection errors, HTTP 429 and 5xx, using exponential backoff with jitter (default 3 attempts). Respect a `Retry-After` header when present. **Never retry other 4xx responses.**
- Gzip the request body when `compression` is enabled, but only if the docs confirm Jitsu accepts `Content-Encoding: gzip`. Otherwise leave this option out.
- On final failure: log via the configured log channel with event count and error (never log the write key), and fire a `Sfere\Events\DeliveryFailed` Laravel event so apps can react.
- Fire `Sfere\Events\EventsSent` after success.
- Put the transport behind an interface (`Sfere\Contracts\Transport`) so it can be swapped.

## 6. Configuration (`config/sfere.php`)

```php
return [
    'enabled'          => env('SFERE_ENABLED', true),
    'host'             => env('SFERE_HOST'),            // e.g. https://your-jitsu-domain.com
    'write_key'        => env('SFERE_WRITE_KEY'),
    'auth_method'      => env('SFERE_AUTH', 'header'),  // header | basic | query
    'endpoint'         => env('SFERE_ENDPOINT', 's2s'), // s2s | standard

    'delivery'         => env('SFERE_DELIVERY', 'batch'), // sync | batch | queue
    'batch' => [
        'max_size'     => 100,
        'max_bytes'    => 500_000,
    ],
    'queue' => [
        'connection'   => env('SFERE_QUEUE_CONNECTION'),
        'name'         => env('SFERE_QUEUE', 'default'),
    ],

    'http' => [
        'timeout'         => 3,
        'connect_timeout' => 2,
        'retries'         => 3,
    ],

    'context' => [
        'include_request' => true, // add ip, userAgent, locale, page.url from the current request
        'static'          => [],   // merged into every event's context
    ],

    'throw_exceptions' => env('SFERE_THROW', false),
    'log_channel'      => env('SFERE_LOG_CHANNEL'),
];
```

Behavior rules:

- If `enabled` is false, or `host`/`write_key` are missing, the SDK becomes a no-op and logs **one** warning per process, not one per event.
- When `context.include_request` is true and a request exists (not in CLI), auto-add `context.ip`, `context.userAgent`, `context.locale` and `context.page.url`. Users can disable this for privacy.

## 7. Testing support for users (`Sfere::fake()`)

Ship a fake, following the pattern of Laravel's `Event::fake()`:

```php
Sfere::fake();

// ... run app code ...

Sfere::assertTracked('Order Completed');
Sfere::assertTracked('Order Completed', fn ($event) => $event['properties']['total'] === 49.99);
Sfere::assertIdentified('user_123');
Sfere::assertNotTracked('Refund Issued');
Sfere::assertNothingSent();
Sfere::assertSentCount(3);
```

The fake records events in memory and makes no HTTP calls.

## 8. Extras

- **Artisan command `sfere:test`** — sends a real test `track` event to the configured Jitsu host and prints success or the error. Useful for verifying credentials.
- **Artisan command `sfere:install`** — publishes the config and prints the env vars to add.
- **Blade directive `@sfereScript`** (optional, phase 5) — outputs Jitsu's official browser snippet using a separate *browser* write key (`SFERE_BROWSER_WRITE_KEY`). Copy the snippet format from the docs; do not hand-write your own tracker.
- **Middleware `Sfere\Http\Middleware\TrackPageViews`** (optional) — sends a `page` event for GET requests that return HTML, with an exclude list for paths like `/horizon*` and `/telescope*`.

## 10. Quality bar

- **Tests:** Pest (or PHPUnit) with `orchestra/testbench`. Use `Http::fake()` and `Http::assertSent()` to verify exact URLs, headers and JSON bodies. Minimum coverage targets:
  - every event type builds the correct payload (including `messageId`, `timestamp`, `sentAt`, `context.library`)
  - all three auth methods produce the correct request
  - batch flushes at `max_size`, at lifecycle end, and splits on `max_bytes`
  - queue mode dispatches the job (use `Queue::fake()`)
  - retries on 429/5xx, no retry on 400/401/403
  - failures don't throw when `throw_exceptions` is false, and do throw when true
  - no-op behavior when disabled or misconfigured
  - `forUser()` and custom resolver
  - the `Sfere::fake()` assertions themselves
- **Static analysis:** Larastan/PHPStan at level 8 with zero errors.
- **Style:** Laravel Pint, default Laravel preset.
- **CI:** GitHub Actions matrix across supported PHP and Laravel versions, running tests, PHPStan and Pint.
- **No hard dependency** beyond `illuminate/*` packages and `ramsey/uuid` (or `Illuminate\Support\Str::uuid()`; prefer this to avoid the extra dependency).

## 11. Phases and acceptance criteria

**Phase 1 — Skeleton**
Composer package, service provider, config publishing, facade, Testbench setup, CI pipeline.
✅ `composer test`, PHPStan and Pint all pass on an empty test suite; the package installs into a fresh Laravel app via a path repository and auto-discovers.

**Phase 2 — Core client, sync delivery**
Payload builders for identify/track/page/group, validation, `HttpTransport` with auth methods, retries, error handling, `forUser()`/`anonymous()`.
✅ All payload and transport tests pass; `php artisan sfere:test` successfully delivers an event to a real Jitsu instance (document how you tested in `NOTES.md`).

**Phase 3 — Batch and queue delivery**
`EventBuffer`, lifecycle flushing, Octane safety, `/v1/batch` support, `SendEvents` job.
✅ Batch and queue tests pass; no events are lost when a request ends; buffer is empty at the start of each Octane request.

**Phase 4 — Testing fake and Laravel events**
`Sfere::fake()` with all assertions, `EventsSent` / `DeliveryFailed` events.
✅ Fake tests pass; README shows how to use the fake.

**Phase 5 — Extras and docs**
`sfere:install`, optional middleware, optional `@sfereScript`, full README.
✅ README covers installation, configuration, every public method, delivery modes, testing, privacy notes and troubleshooting. CHANGELOG has a `1.0.0` entry.

## 12. Non-goals (do not build)

- A browser JavaScript tracker (use Jitsu's official snippet).
- Reading data back from Jitsu or managing Jitsu configuration via its Management API.
- Destination-specific logic (Mixpanel, GA4, etc.); Jitsu handles routing.
- A persistent disk/database queue of its own; rely on Laravel queues for durability.

---

## 13. Definition of done

The package can be installed with `composer require sfere/sfere-sdk`, configured with two env vars (`SFERE_HOST`, `SFERE_WRITE_KEY`), and used with one line (`Sfere::track(...)`) to deliver events to Jitsu reliably, without ever crashing the host app, with full tests, static analysis and documentation passing in CI.
